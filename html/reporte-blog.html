Delimitacion del Problema

El problema central de este proyecto consiste en la prediccion del riesgo de credito para solicitantes de prestamos. En el sector financiero, la capacidad de identificar que clientes tienen una alta probabilidad de incumplimiento (default) es critica para mantener la salud de la cartera y minimizar las perdidas crediticias.

Marco Teórico

Para fundamentar el diseño del sistema propuesto, se presentan a continuación las definiciones técnicas que sustentan cada componente del pipeline de modelamiento.

1. Riesgo de Crédito y Default

El riesgo de crédito se define como la posibilidad de que un deudor incumpla sus obligaciones financieras contractuales, generando una pérdida económica para el acreedor (Siddiqi, 2012). Dentro de este marco, el evento de default representa el punto en que dicha pérdida se materializa: formalmente, ocurre cuando el prestatario acumula retrasos superiores a 90 días o cuando la entidad acreedora reconoce la deuda como incobrable (charge-off) (Siddiqi, 2012). La gestión cuantitativa de este riesgo mediante modelos estadísticos constituye la base de los sistemas modernos de otorgamiento de crédito.

2. Clasificación Binaria y Desbalance de Clases

La predicción de default se enmarca en los problemas de clasificación binaria supervisada, donde el objetivo es aprender una función f: X → {0, 1} a partir de un conjunto de pares (características, etiqueta) (Pedregosa et al., 2011). Un desafío inherente a este dominio es el desbalance de clases: los eventos de default son estadísticamente minoritarios respecto a los pagos exitosos. Sin una estrategia correctiva, un clasificador naïve que prediga siempre la clase mayoritaria puede alcanzar alta exactitud global (accuracy) sin detectar ningún incumplimiento real. Para mitigarlo, técnicas como la ponderación de clases (class weighting) penalizan asimétricamente los errores en la clase minoritaria durante el entrenamiento (Pedregosa et al., 2011).

3. Regresión Logística

La regresión logística es un modelo lineal generalizado que estima la probabilidad de pertenencia a una clase mediante la función sigmoide aplicada a una combinación lineal de las variables predictoras (Pedregosa et al., 2011). Su amplia adopción en la industria financiera se debe a su alta interpretabilidad: los coeficientes del modelo permiten cuantificar directamente la contribución marginal de cada variable al riesgo de default, lo que facilita la auditoría regulatoria y la comunicación con equipos de negocio (Siddiqi, 2012). En el contexto de este proyecto, el modelo de regresión logística cumple el rol de baseline (línea base), estableciendo un umbral de rendimiento que el modelo avanzado debe superar.

4. Red Neuronal Artificial (Perceptrón Multicapa — MLP)

Un Perceptrón Multicapa (MLP) es una arquitectura de red neuronal feedforward compuesta por una capa de entrada, una o más capas ocultas con funciones de activación no lineales, y una capa de salida (LeCun et al., 2015). La función de activación ReLU (Rectified Linear Unit), definida como f(x) = max(0, x), permite modelar relaciones no lineales entre las variables sin el problema del desvanecimiento del gradiente (vanishing gradient). El entrenamiento se realiza mediante el algoritmo de retropropagación (backpropagation) combinado con el optimizador Adam, que ajusta adaptativamente la tasa de aprendizaje para cada parámetro (Paszke et al., 2019). La implementación se realizó en el framework PyTorch, que permite la diferenciación automática y la ejecución en GPU para conjuntos de datos de gran escala (Paszke et al., 2019).

5. Métricas de Evaluación en Clasificación Desbalanceada

En problemas con desbalance de clases, la exactitud global (accuracy) resulta insuficiente como única métrica de evaluación. Se emplean métricas complementarias (Pedregosa et al., 2011):

Métrica Fórmula Interpretación en el contexto de crédito
Precisión (Precision) VP / (VP + FP) De cada alerta de default emitida, ¿cuántas son correctas?
Recall (Sensibilidad) VP / (VP + FN) Del total de defaults reales, ¿cuántos detecta el modelo?
F1-Score 2 · (P · R) / (P + R) Media armónica entre Precisión y Recall.
AUC-ROC Área bajo la curva ROC Capacidad global de discriminación entre clases (0.5 = aleatorio, 1.0 = perfecto).

VP = Verdaderos Positivos, FP = Falsos Positivos, FN = Falsos Negativos. Fuente: Pedregosa et al. (2011).

6. Scorecard de Crédito

Un Scorecard es un instrumento de decisión estandarizado que traduce la probabilidad de default estimada por un modelo estadístico en un puntaje numérico comprensible para los equipos de negocio (Siddiqi, 2012). La transformación se basa en los odds de pago (razón entre la probabilidad de buen pagador y la de mal pagador), expresados en escala logarítmica. Los parámetros de calibración — Offset y Factor — permiten anclar el puntaje a una escala predefinida (comúnmente 300–850 puntos, equivalente a la escala FICO) y definir cuántos puntos corresponden a duplicar los odds (Points to Double the Odds, PDO) (Siddiqi, 2012). Esta calibración garantiza la comparabilidad del modelo con los estándares de la industria bancaria internacional.

Fórmula General del Scorecard Siddiqi, 2012
Score = Offset + Factor × ln((1 − p) / p)

Factor = PDO / ln(2)  |  Offset = target_score − Factor × ln(target_odds)

Donde p es la probabilidad de default estimada por el modelo, PDO es el número de puntos que duplican los odds, y target_score / target_odds son los parámetros de anclaje (en este proyecto: 600 puntos a 50:1 odds, PDO = 20).

Metodologia Planteada

Para resolver este problema, se siguio una metodologia basada en el estandar de la industria, estructurada en las siguientes fases:

Fase A: Ingenieria y Preparacion de Datos

Se implemento un pipeline de transformacion que incluyo:

  • Limpieza Dimensional: Reduccion de 68 variables originales a ~66 caracteristicas finales tras la aplicacion de One-Hot Encoding (OHE).
  • Tratamiento de Nulos: Uso de Flags Centinela para capturar la ausencia de datos en variables criticas (como meses desde el ultimo retraso) y la imputacion por la mediana para el resto de valores numericos.
  • Normalizacion: Aplicacion de un StandardScaler para asegurar que las variables con diferentes magnitudes (como annual_inc vs dti) tengan el mismo peso en el entrenamiento de la red neuronal (Pedregosa et al., 2011).

Arquitectura de la Red Neuronal

La red neuronal fue implementada en PyTorch con una arquitectura tipo MLP (Perceptron Multicapa). Dado el desbalance de clases (78.1% No Default vs 21.9% Default), se utilizo BCEWithLogitsLoss con un pos_weight = 3.57 (razon negativos/positivos), lo que penaliza mas los errores en la clase minoritaria (Siddiqi, 2012).

Arquitectura: Input(73) → 64 → 32 → 16 → 1
Capa Entrada Salida Activacion Regularizacion
Capa 1 73 features 64 neuronas ReLU BatchNorm + Dropout(0.2)
Capa 2 64 neuronas 32 neuronas ReLU BatchNorm + Dropout(0.2)
Capa 3 32 neuronas 16 neuronas ReLU BatchNorm (sin Dropout)
Salida 16 neuronas 1 (logit) Sigmoid* —

* La activacion Sigmoid se aplica internamente por BCEWithLogitsLoss durante el entrenamiento. La capa 3 omite Dropout deliberadamente para preservar representaciones antes de la salida. Total de parametros entrenables: 7.585.

Optimizador

Adam — lr=0.001, weight_decay=1e-4

Funcion de perdida

Scheduler

Epocas / Batch

30 epocas — batch size=512

Estrategia ante el Desbalance de Clases

El dataset presenta un desbalance significativo: 78.1% No Default vs 21.9% Default. Sin correccion, el modelo aprenderia a predecir siempre "No Default" y obtendria un accuracy aparentemente alto sin detectar ningun riesgo real. Para mitigarlo, se calculo pos_weight = n_negativos / n_positivos = 3.57, que se pasa directamente a BCEWithLogitsLoss. Esto hace que cada error en la clase Default cueste 3.57 veces mas que un error en la clase No Default, forzando al modelo a prestarle atencion a la clase minoritaria durante el entrenamiento (Pedregosa et al., 2011).

Comportamiento de los Modelos

Como se puede observar en la tabla, el balance entre Falsos Positivos y Falsos Negativos es la diferencia mas importante ya que los modelos tienen comportamientos opuestos:

¿Que significa Precision = 0.43?

Una Precision de 0.43 en la clase Default significa que, de cada 100 alertas de incumplimiento que genera el modelo, 43 corresponden a casos reales y 57 son falsos positivos — clientes que el modelo marco como riesgosos pero que en realidad habrian pagado. Este valor es el resultado directo de la estrategia conservadora adoptada: priorizar que las alertas sean confiables, aunque se detecten menos defaults en total. En el contexto financiero, esto equivale a rechazar incorrectamente a 57 buenos clientes por cada 100 alertas emitidas (Siddiqi, 2012).

La red neuronal tiende a ser conservadora, tiene una precision mas alta (0.43), lo que significa que cuando dice que alguien entrara en default, es mas probable que tenga razon. Sin embargo, debido a su bajo recall (0.36), se le escapan muchos casos reales de default.

La regresion logistica tiende a ser mas agresiva, tiene un recall mucho mas alto (0.63), por lo que es mucho mejor para detectar a las personas que entraran en default. Todo esto al costo de tener una precision baja (0.34), es decir, genera muchos "falsos alarmistas" — clasifica como default a gente que en realidad pagaria.

El modelo confirma que los ingresos anuales (annual_inc) son el mayor contrapeso natural a la deuda, reforzando principios establecidos de la banca tradicional (Siddiqi, 2012).

Analisis de Riesgo

¿Que Variables Hacen Mas Riesgosa a una Persona?

Para responder esta pregunta, se analizaron los coeficientes de la Regresion Logistica, que por su naturaleza lineal permite cuantificar directamente el impacto de cada variable sobre la probabilidad de default. Un coeficiente positivo aumenta el riesgo; uno negativo lo reduce (Siddiqi, 2012).

Variables que Aumentan el Riesgo

Factor 1 — Tasa de Interes (int_rate)

Es el predictor de riesgo mas fuerte. Una tasa de interes alta no es coincidencia: las entidades financieras ya la asignan en funcion del perfil de riesgo del solicitante. Es decir, la tasa de interes actua como un proxy del riesgo percibido por el mercado. A mayor tasa, mayor presion sobre el flujo de caja del prestatario y mayor probabilidad de incumplimiento.

Factor 2 — Ratio Deuda-Ingreso (dti)

Mide que proporcion del ingreso mensual del solicitante ya esta comprometida con otras deudas. Un DTI alto indica que el cliente tiene poco margen para absorber un nuevo pago, lo que eleva directamente la probabilidad de default. Es uno de los indicadores mas utilizados en la banca tradicional para evaluar capacidad de pago (Siddiqi, 2012).

Factor 3 — Plazo de 60 Meses (term_60 months)

Como se evidencio en el analisis descriptivo, los prestamos a 60 meses tienen una tasa de default de aproximadamente 39%, frente al 16% de los prestamos a 36 meses. Un plazo extendido expone al prestatario a mas ciclos de incertidumbre economica — cambios de empleo, gastos imprevistos, crisis — aumentando la probabilidad de que en algun punto del periodo no pueda cumplir con el pago.

Variables que Reducen el Riesgo

Factor 4 — Ingresos Anuales (annual_inc)

Es el mayor contrapeso natural al riesgo. Un ingreso anual elevado indica mayor capacidad para absorber obligaciones financieras sin comprometer el flujo de caja. El modelo confirma que los ingresos anuales son la variable protectora mas fuerte, reforzando principios establecidos de la banca tradicional (Siddiqi, 2012).

Factor 5 — Ausencia de Registros de Mora (mths_since_last_delinq)

Gracias al uso de Flags Centinela en el preprocesamiento, se identifico que la ausencia de un registro de mora es en si misma una senal de alta calidad crediticia. Un cliente que nunca ha tenido un retraso en sus pagos representa significativamente menos riesgo que uno con historial de morosidad, incluso si ese historial es antiguo.

"El perfil de mayor riesgo es un solicitante con alta tasa de interes, alto DTI, plazo de 60 meses e ingresos bajos. El perfil de menor riesgo es el opuesto: tasa baja, DTI bajo, plazo de 36 meses, ingresos altos y sin historial de mora."

Reflexiones

Aprendizajes del Proceso de Modelamiento

A lo largo de las etapas de preprocesamiento, entrenamiento y validacion del modelo de riesgo, se generaron los siguientes aprendizajes tecnicos y de negocio:

I. Sobre la Naturaleza del Riesgo (Insights de Negocio)

  • El factor tiempo es determinante: Se aprendio que el plazo del prestamo (term) no es solo una variable de pago, sino el predictor de riesgo mas agresivo. Los prestamos a 60 meses actuan como un multiplicador de la probabilidad de default, posiblemente porque exponen al prestatario a mas ciclos de incertidumbre economica.
  • Los ingresos son determinantes: Los ingresos anuales (annual_inc) son el mayor contrapeso natural a la deuda.
  • El silencio de los datos es informacion: El tratamiento de los valores nulos mediante Flags Centinela (ej. mths_since_last_delinq) revelo que la ausencia de un registro de mora es, en si misma, una de las senales de mayor calidad crediticia, y no debe tratarse simplemente como un dato faltante.

II. Sobre la Tecnica de Modelado (Machine Learning)

  • Distintos casos de uso: Se aprendio que aunque ambos modelos tienen una capacidad de discriminacion similar, cada uno se "especializa" en un escenario especifico.
  • Fuga de datos (Data Leakage): El aprendizaje mas critico en la fase inicial fue la importancia de filtrar variables "post-aprobacion". Incluir informacion sobre intereses pagados o estados de cuenta actuales habria inflado artificialmente el exito del modelo, volviendolo inutil para aplicaciones en tiempo real.

III. Sobre la Implementacion (Scorecard y App)

  • Probabilidad vs. Puntaje: Se aprendio que la probabilidad matematica pura (0.0 a 1.0) es dificil de digerir para el usuario final. La implementacion de la Scorecard (escala 300-850) fue esencial para transformar un output estadistico en una herramienta de decision de negocio intuitiva.
  • Calibracion de la Scorecard: Ajustar el factor y el offset permitio alinear el modelo con los estandares bancarios tradicionales, demostrando que el modelador debe ser el puente entre la ciencia de datos y las necesidades del mundo real.

Caso de Uso: RiskScore AI — Sistema de Apoyo a la Decision

Para tangibilizar los resultados del modelo, se desarrollo la aplicacion RiskScore AI, una plataforma web disenada para ser utilizada por analistas de credito en entidades financieras o plataformas Fintech. El caso de uso se centra en la evaluacion inmediata de solicitudes de prestamo.

Ademas del uso institucional, la aplicacion RiskScore AI esta disenada como una herramienta de "Autoservicio" (Self-service) para el usuario final (el solicitante). Este caso de uso se enfoca en la transparencia financiera y la preparacion previa a una solicitud formal de credito.

Escenarios de Aplicacion

Aplicacion I — Analisis Institucional

Cuando un cliente solicita un credito a traves de la plataforma, el analista de riesgo no necesita interpretar complejas probabilidades matematicas. En su lugar, ingresa el perfil socioeconomico del solicitante en la interfaz de RiskScore AI.

Aplicacion II — Autoservicio para el Usuario Final

Un usuario comun, antes de someterse a un proceso formal (el cual suele implicar una consulta a las centrales de riesgo que puede afectar su historial), utiliza la pagina web para realizar una simulacion privada. Esto le permite entender como lo percibe un algoritmo de Inteligencia Artificial.

Flujo de Operacion

1
Ingreso de Datos
El usuario introduce variables clave como el ingreso anual, el monto solicitado, la ratio de deuda (DTI) y la antiguedad laboral.
2
Procesamiento en Tiempo Real
La aplicacion aplica automaticamente el pipeline de limpieza (OHE y escalado) y consulta la Red Neuronal (PyTorch).
3
Conversion a Scorecard
La probabilidad generada por la red es transformada a una escala de 300 a 850 puntos.
4
Resultado e Interpretacion
El sistema entrega un semaforo de riesgo con recomendacion de decision.

Sistema de Semaforos de Riesgo

El sistema entrega un diagnostico visual mediante tres categorias de riesgo claramente diferenciadas:

VERDE — Riesgo Bajo
Score > 650
Recomendacion de aprobacion automatica. El perfil del solicitante presenta caracteristicas solidas de pago.
AMARILLO — Riesgo Moderado
500 - 650 puntos
Requiere revision manual de garantias. El perfil presenta elementos de riesgo que deben ser evaluados por un analista.
ROJO — Riesgo Alto
Score < 500
Recomendacion de rechazo. La probabilidad de incumplimiento supera los umbrales aceptables de riesgo.

Valor Agregado para el Negocio

Dias → Segundos
Velocidad de respuesta
100%
Consistencia en criterios
Beneficios Clave

Velocidad: Reduce el tiempo de respuesta de dias a segundos. Consistencia: Elimina el sesgo humano en la evaluacion inicial, aplicando los mismos criterios tecnicos a todos los solicitantes.
